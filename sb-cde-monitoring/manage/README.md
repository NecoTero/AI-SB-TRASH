# Реестр управления проектом «Мониторинг»

Актуальность аудита: 22.10.2026.

Этот каталог собирает в одном месте вопросы, задачи и известные дефекты, найденные при сопоставлении требований, документации, реализации, локальных данных и тестов.

## Файлы

- [HIGH_LEVEL_FUNCTIONALITY.md](HIGH_LEVEL_FUNCTIONALITY.md) — верхнеуровневая продуктовая декомпозиция: график, IFC, сопоставление работ и таймлайн.
- [OPEN_QUESTIONS_AND_TASKS.md](OPEN_QUESTIONS_AND_TASKS.md) — решения, которые нужно принять, и приоритизированный технический бэклог.
- [KNOWN_ISSUES_AND_CONTRADICTIONS.md](KNOWN_ISSUES_AND_CONTRADICTIONS.md) — временный реестр подтверждённых ошибок, костылей, рисков и противоречий.
- [XLSX_IMPORT_IFC_STATUS_MAPPING.md](XLSX_IMPORT_IFC_STATUS_MAPPING.md) — контракт импорта единой XLSX-формы, ограничения статусной модели и схема маппинга работ с IFC.

## Как пользоваться

1. Новому пункту присваивается стабильный идентификатор.
2. После решения вопроса результат переносится в основную спецификацию или профильный документ, а пункт закрывается ссылкой на решение.
3. Файл известных проблем не является новой спецификацией: он фиксирует расхождения, но не выбирает бизнес-правило вместо пользователя.
4. Приоритеты: **P0** — риск неверных данных/неработающий механизм; **P1** — существенный функциональный или эксплуатационный недостаток; **P2** — технический долг и качество сопровождения.

## Иерархия источников требований

Сейчас она фактически неоднозначна. До консолидации безопасный порядок такой:

1. последние явные уточнения пользователя;
2. `Статусы и маппинг IFC Временный/STATUS_RULES.md` для статусной модели;
3. `PROJECT_SPEC.md` для общей модели продукта;
4. `README.md` как описание текущей реализации, но не источник новых требований.

Неоднозначность этой иерархии сама зарегистрирована как открытый вопрос.
