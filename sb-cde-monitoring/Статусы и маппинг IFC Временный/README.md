# SB_CDE: база строительных элементов IFC для 4D/5D

**Источник модели:** `RD_KR_04-08.ifc` (IFC4, из Revit 2024).  
**Источник КФО:** предоставленный `Справочники_Работ.xlsx`, листы `Справочник КФО`, `DATA`, `Классификатор BIM элементов`.

## Состав

| Файл | Назначение |
|---|---|
| `data/sb_cde_elements.sqlite` | Готовая SQLite БД; удобно подключить из backend / через расширение VS Code SQLite Viewer |
| `data/model_elements.json` | Все 621 сохранённых элемента, **полные IFC property sets**, QTO и вычисленные пользовательские поля |
| `data/custom_parameters_by_guid.json` | Лёгкое соответствие `IFC GlobalId -> Код КФО, КФО, Корпус, Секция, Этаж`; подходит как слой атрибутов в 3D-вьювере |
| `data/model_elements.csv` | Плоская таблица (UTF-8 BOM; разделитель `;`) |
| `data/kfo_catalog.json` | Весь справочник КФО из Excel (включая исходный дублирующийся код) |
| `data/kfo_class_links.json` | Связи «КФО ↔ класс BIM» из листа `DATA`, включая исходные признаки `BIM` |
| `data/bim_class_catalog.json` | Классы BIM-элементов из Excel |
| `data/excluded_elements.json` | Исключённые 305 проёмов и 1 вспомогательный объект с причиной |
| `scripts/build_database.py` | Повторный импорт из IFC, Python 3, только стандартная библиотека |
| `src/types.ts`, `src/adapter.ts` | TypeScript-модель и адаптер для веб-приложения |
| `reports/audit.json`, `reports/mapping_audit.md` | Статистика, расшифровка правил и перечень нерешённых вопросов |
| `source/RD_KR_04-08.ifc` | Оригинальная IFC-геометрия для загрузки в 3D-вьювер |
| `source/Справочники_Работ.xlsx` | Исходный справочник (для проверки происхождения КФО) |

## Подключение в VS Code

1. Распакуйте архив в корень проекта либо вложите папку `SB_CDE_IFC_DB` в проект.
2. Для фронтенда с TypeScript включите `"resolveJsonModule": true` в `tsconfig.json`.
3. Импортируйте готовый адаптер:

```ts
import { elements, customParamsByGuid, findElements, build4DTree } from './SB_CDE_IFC_DB/src/adapter';

const basement = findElements({ building: 'Корпус Б', floor: 'Этаж -1' });
const issues = findElements({ reviewOnly: true });
const tree = build4DTree();
const kfo = customParamsByGuid['2V5ts6Jp15OgoLWYPTfr2W']['Код КФО'];
```

4. Для backend используйте SQLite и `GUID` как внешний ключ к IFC-объекту:

```sql
SELECT guid, name, building, floor, kfo_code, volume_m3
FROM elements
WHERE building = 'Корпус В' AND floor = 'Этаж 1'
ORDER BY kfo_code, guid;
```

Файл SQLite можно открыть непосредственно в VS Code, если установлено расширение для просмотра SQLite. Для просмотра исходной геометрии в 3D нужно загрузить `source/RD_KR_04-08.ifc` во вьювер и соединять его элементы с таблицей по `guid` / IFC `GlobalId`. **В SQLite и JSON хранится описание элементов, но не триангулированные меши**. Содержимое оригинального IFC не изменено.

## Правила назначения

**Подтверждённые исходные атрибуты:** `О_Здание`, `О_Этаж`, `Объем`, `Категория`, `Семейство`, `Тип`, `О_Материал`, `О_Шифр тома`; исходный IFC-класс, IFC `GlobalId`, пространственный контейнер. В исходном IFC нет готового присвоения именно кодов КФО из предоставленного справочника.

**[Inference] Добавленные атрибуты:** `Код КФО`, `КФО`, `Корпус`, `Секция`, `Этаж` как виртуальный слой БД. `Корпус`/`Этаж` берутся из точных исходных пользовательских свойств. `Секция = null` (секции отсутствуют). КФО рассчитывается по IFC-классу, семейству, этажу и таблице `DATA`.

| Правило | Код | Что назначаем |
|---|---|---|
| Класс несущих конструкций, `О_Этаж = Этаж -1` | `204.02.02.05` | Монолитные конструкции ниже 0 |
| IFC стены/колонны, `О_Этаж = Этаж 1` | `204.02.03.01` | Монолитные стены и колонны выше 0 |
| IFC балки/плиты, `О_Этаж = Этаж 1` | `204.02.03.02` | Монолитные плиты и прочие конструкции выше 0 |
| Семейство «КЖ3_Засыпка песком» | `204.02.01.04` | **Гипотеза:** обратная засыпка с уплотнением (проверить соответствие) |
| Семейство «Пластина для анкеровки» | `204.02.03.05` | **Гипотеза:** второстепенные металлоконструкции (проверить) |

**Важно:** деление «ниже/выше 0» в данном прототипе реализовано **по пользовательскому параметру `О_Этаж`**, а не геометрическим пересечением фактической плоскости 0.000. Это правило может потребовать изменения для переходящих через отметку 0 конструкций и элементов, лежащих на границе этажей. Класс `IfcBuildingElementProxy` сопоставляется с КР.05 по имени семейства/категории предположительно, поэтому все такие элементы помечены `review`.

Статусы `kfoStatus`: `rule_based` — автоматическое правило, **не ручная верификация**; `review` — требует проверки специалистом; `unmapped` — правило не дало кода. Коды справочника не придуманы: все присвоенные коды присутствуют в предоставленном Excel.

## Проверка данных

- 67 486 STEP-записей обработано, 622 объекта классов `IfcWall`, `IfcSlab`, `IfcBeam`, `IfcColumn`, `IfcBuildingElementProxy` обнаружено.
- 621 физический элемент включён. Исключено: 305 `IfcOpeningElement` и 1 вспомогательная `IfcColumn` с комментарием «для подрезки балки».
- 621 / 621 имеет физический объём из параметра `Объем`; все значения сравнили с `Qto_* / NetVolume` без расхождений больше `0.00001 м³`.
- 551 назначение — `rule_based` и 70 — `review` (68 `IfcBuildingElementProxy` плюс 2 специальных случая).
- В справочнике КФО один **конфликт кодов**: `205.01.01.01` встречается как «Очистка» и «Химическая очистка». Оба варианта сохранены в таблице `kfo_catalog_variants`. Этот код не используется для текущей модели.

## Схема базы

- `elements` — 621 объект, включая `properties_json`, `quantities_json`, `property_sets_json`, расчётные поля.
- `element_properties` — нормализованные исходные свойства (параметр + PropertySet + тип + значение).
- `excluded_elements` — исключённые объекты.
- `storeys` — уровни IFC по пространственной структуре.
- `kfo_catalog`, `kfo_catalog_variants`, `bim_classes`, `kfo_class_links` — справочная часть.
- `vw_4d_elements` — компактное представление для 4D.

Пример SQL для поиска элементов одного КФО:

```sql
SELECT building, floor, kfo_code, COUNT(*) AS elements,
       ROUND(SUM(volume_m3), 3) AS volume_m3
FROM elements
GROUP BY building, floor, kfo_code
ORDER BY building, floor, kfo_code;
```

Получение значения любого исходного Revit-параметра:

```sql
SELECT e.guid, e.name, p.value_text
FROM elements e
JOIN element_properties p ON p.guid = e.guid
WHERE p.property_name = 'О_Марка'
ORDER BY e.guid;
```

## Пересборка

```bash
python SB_CDE_IFC_DB/scripts/build_database.py --ifc SB_CDE_IFC_DB/source/RD_KR_04-08.ifc
```

После запуска будут обновлены SQLite, JSON, CSV и аудит. Для изменения правил назначения смотрите функцию `extract()` в `scripts/build_database.py`. Вся логика извлечения IFC реализована на Python без `ifcopenshell`, поскольку в среде подготовки пакета он не был доступен.
