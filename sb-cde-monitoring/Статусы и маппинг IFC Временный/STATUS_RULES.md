# Статусы операций СМР на дату T

Редакция: 19.10.2026, после итоговых уточнений пользователя. Проект SB_CDE.

Документ заменяет предыдущие редакции STATUS_RULES.md. При расхождении старых проектных документов со статусными правилами использовать эту редакцию. Дополнения, которые пользователь не определил, явно отмечены как технические проверки или открытые случаи; не заполнять их догадками.

## 1. Контекст

- T — выбранная дата шкалы.
- A — актуальная версия графика в текущем контексте просмотра.
- R — её отчётная дата.
- B — соответствующая базовая версия для сравнения.
- ФН, ФО — фактическое начало и окончание операции из A.
- АН, АО — плановое начало и окончание операции из A.
- БН, БО — плановое начало и окончание соответствующей операции из B.

Статусы считать отдельно для каждой операции. КФО — группировка, не уникальный ключ. Сохранять связь результата с операцией, A, B и T; при смене контекста пересчитывать, не менять исходные снимки.

Три независимых показателя:

| Показатель | Значения |
| --- | --- |
| Статус на момент T | Факт / План |
| Статус СМР | Не начато / В работе / Завершено |
| Отклонение по датам относительно B | Просрочена / По графику / Опережение |

Объём и процент хранятся как фактические показатели, но не определяют перечисленные статусы. Статус сравнения объёмов с планом в текущей версии не рассчитывается.

## 2. Временные границы

| Условие | Область T |
| --- | --- |
| T ≤ R | Факт |
| T > R | План |

Правило отчётного периода продолжительностью семь дней ОТМЕНЕНО. Не прибавлять к R шесть дней, не размножать один статус на неделю. Сравнивать конкретные даты.

В день начала операция уже «В работе»; в день окончания — «Завершено». Для пользовательского дневного режима сравнивать календарные даты, не допускать случайного сдвига из-за преобразования часового пояса. Исходные значения времени XML сохранять. Рабочий календарь XML используется для шагов шкалы; он не создаёт семидневную область факта.

«Факт / План» описывает положение T относительно R. Фактически завершённая операция остаётся завершённой и в плановой области; источник её завершения при этом остаётся фактическим.

## 3. Статус СМР: фактическая область

Использовать только даты A, без сравнения с B и без расчёта по процентам/объёму. Для непротиворечивых данных применять условия в указанном порядке:

| Приоритет | Условие | Статус |
| --- | --- | --- |
| 1 | ФО задано и ФО ≤ T | Завершено |
| 2 | ФН задано и ФН ≤ T, а ФО отсутствует или ФО > T | В работе |
| 3 | ФН позже T либо фактического начала нет | Не начато |

Отсутствие начала у ещё не начатой операции допустимо. При окончании без начала, обратном порядке дат или признаках ошибки импорта не маскировать противоречие статусом «Не начато»: сохранить данные и показать диагностику.

## 4. Статус СМР: плановая область

Сначала учитывать известный факт, затем плановые сроки. Два принципиально разных случая:

1. Плановое окончание уже прошло к R, но фактического окончания нет: операция остаётся «В работе» и «Просрочена». Не завершать её автоматически при перемещении T вправо.
2. Плановое окончание находится в будущем относительно R: при достижении этой даты T операция может стать «Завершено» с признаком «План».

Порядок расчёта для корректных данных:

| Приоритет | Условие при T > R | Статус СМР | Отклонение |
| --- | --- | --- | --- |
| 1 | ФО задано и ФО ≤ R | Завершено | По фактическому окончанию относительно БО |
| 2 | ФО нет, АО < R | В работе | Просрочена; причина — пропущенное плановое окончание без факта |
| 3 | ФО нет, АО > R и T ≥ АО | Завершено | Плановое сравнение окончания с БО |
| 4 | Фактическое начало уже известно либо АН ≤ T < АО | В работе | По разделу 5 |
| 5 | Фактического начала нет и T < АН | Не начато | По разделу 5 |

Если АО уже прошло, но фактического начала также нет, правило пользователя «В работе + Просрочена» сохранять как правило отображения, а отсутствие начала выводить отдельной диагностикой. Не создавать ФН или ФО для согласования данных с картинкой.

Плановое «Завершено» не создаёт факт окончания, фактический объём или 100% фактического выполнения. Фактически начатую операцию не возвращать в «Не начато» из-за планового начала в будущем; фактически завершённую не возвращать в «В работе».

Граничный случай АО = R при отсутствии ФО не обсуждался отдельно: перед его реализацией уточнить, считать ли окончание пропущенным по завершении отчётного дня. Нужные даты отсутствуют — показать диагностику; не придумывать сроки.

## 5. Отклонение по датам относительно базового графика

Объёмы не участвуют. Простое равенство состояний A и B НЕ означает «По графику». Прежняя матрица, где «В работе / В работе» и «Завершено / Завершено» автоматически считались «По графику», отменена.

### 5.1. До завершения

- Если по B операция должна была начаться на T, но фактически ещё не началась — «Просрочена».
- Если началась позже БН — «Просрочена», даже когда обе версии показывают «В работе».
- Если базовое окончание прошло, но завершения нет — «Просрочена».
- Пропущенное к R плановое окончание A без ФО — «Просрочена», как установлено разделом 4; хранить причину отдельно от сравнения с B.

Для проверки задержки начала использовать ФН в фактической области, а в плановой — известное ФН, иначе АН. Не использовать ещё не наступившее фактическое начало как событие, уже произошедшее на T.

Пользователь определил приоритет: позднее начало остаётся просрочкой до завершения. Будущее раннее окончание не снимает фактическую задержку начала до наступления завершения.

### 5.2. После завершения

При достижении фактического окончания итог определяется окончанием, а не началом:

| Условие | Итог |
| --- | --- |
| ФО < БО | Опережение |
| ФО = БО | По графику |
| ФО > БО | Просрочена |

Примеры: началась позже, закончилась раньше — до завершения просрочена, после завершения опережение. Началась раньше, закончилась позже — после завершения просрочена. Историческое отклонение начала можно хранить, но оно не переопределяет итог завершённой операции.

Для планового завершения справа от R сравнивать АО с БО аналогично и показывать признак «План». Это формализация ранее согласованного планового просмотра, не запись факта.

### 5.3. Полнота алгоритма

[Inference] Предлагаемое дополнение для незадержанных незавершённых операций: раннее начало — «Опережение», начало в базовую дату — «По графику»; если обе ещё не начаты и базовое начало не наступило — «По графику на T». Эти случаи не были отдельно подтверждены после отмены старой матрицы. Не выдавать их за явно согласованные формулы; уточнить при реализации соответствующей ветви.

Если операции B нет — «Нет базы для сравнения», а не «По графику». Если дат недостаточно — «Нет данных для сравнения». Специальную просрочку из раздела 4 при этом можно показывать с её собственной причиной, не выдавая её за вычисленное отклонение от отсутствующей базы.

## 6. История фактических объёмов и процентов

В каждом актуальном графике указан накопленный факт на его R. Сохранять отдельно для каждой операции:

- идентификатор версии графика;
- отчётную дату;
- накопленный фактический объём и единицу измерения;
- фактический процент из источника, если он есть.

Накопленные итоги разных версий НЕ складывать. Исторический объём искать в предыдущих графиках по их отчётным датам. Новая загрузка не переписывает прежние значения.

Планового процента выполнения на произвольную T нет. Не создавать его, не распределять общий объём по дням и не интерполировать план. Не сравнивать факт с искусственно созданным плановым процентом или постоянными 100% для присвоения «Меньше по графику / По графику / Больше по графику». Этот статус сейчас не рассчитывается.

Порядок показа факта между отчётными датами или при пропуске графика отдельно не согласован: не выдавать последнее известное значение за измеренное на T. Можно показывать сохранённые точки с их реальными датами. Прогноз фактического объёма справа от R не строить.

## 7. Идентичность, новые и удалённые операции

ID операции — предварительный ключ сопоставления. В XML есть также UID и Spider_Code. Стабильность ID между экспортами ещё не подтверждена: проверить на втором XML, сохранить все исходные идентификаторы. Не объявлять номера строк или WBS стабильным ключом без проверки.

- Новая операция, которой нет в B: «Нет базы для сравнения».
- Операция отсутствует в следующей версии: сохранить историю, пометить «Удалена из актуального графика», не удалять физически.
- Статус наличия/удаления — отдельный признак, не статус СМР. Не считать удаление завершением.

## 8. IFC

Один IFC-элемент относится только к одной работе. Не реализовывать конфликт цветов от нескольких работ. Операции одного КФО не сливать. Конкретный маппинг работы на операцию должен сохранять однозначность расчёта цвета; правила текущего IFC согласуются отдельно.

Цвет по статусу СМР: «Не начато» — элемент скрыт; «В работе» — зеленовато-синий/болотный; «Завершено» — зелёный. Начальный обзор всей модели с прозрачностью 40% — отдельный режим, не статус.

Признак «Факт / План» и отклонение показывать отдельно; не менять цветовую схему без согласования.

## 9. Проверки

1. T до начала, в день начала, внутри интервала, в день окончания и после окончания.
2. T = R даёт «Факт»; T > R — «План», без недельного продления.
3. Позднее начало при одинаковом «В работе» даёт просрочку.
4. Позднее начало и раннее фактическое окончание: смена просрочки на опережение при завершении.
5. Обе операции завершены, но ФО > БО: просрочка сохраняется.
6. АО < R, ФО нет: «В работе + Просрочена», без автоматического планового завершения.
7. АО > R, T ≥ АО: плановое завершение без создания ФО/фактического объёма.
8. Отдельное хранение накопленных фактов без суммирования снимков.
9. Новая/удалённая операция и отсутствие базы сравнения.
10. Сохранение исходных данных и диагностика некорректных дат.

В проверенном исходном XML по 1 527 операциям СМР не обнаружены: ФО без ФН, обратный порядок фактических или плановых дат, фактические даты после R и незавершённые операции с плановым окончанием до R. У 1 054 операций отсутствовало ФН; само по себе это не ошибка. Это результаты проверки одного образца, не гарантия качества других загрузок.

## 10. Оставшиеся технические проверки

- Подтвердить стабильность ID вторым экспортом.
- Проверить соответствие бизнес-полей дат, объёмов и процентов реальным полям XML; не считать Work физическим объёмом по названию.
- Обработать неизвестные/противоречивые даты без выдуманного статуса.
- Уточнить только явно отмеченные граничные/дополнительные ветви; не возвращать отменённые семь дней, плановый процент и старую матрицу равных состояний.
