# Инструкции агенту: SB_CDE — мониторинг строительства

## Граница локального проекта

Этот каталог — самостоятельный локальный проект. Работай только с файлами внутри папки `sb-cde-monitoring`. Не просматривай, не ищи, не запускай и не изменяй файлы соседних проектов в `C:\SB`, не заимствуй оттуда код или данные. Выход за эту границу допустим только по отдельному явному запросу пользователя с указанием затрагиваемых проектов.

## Назначение
Создать с нуля локальный работающий макет инструмента 4D/5D мониторинга. Первая версия включает реальный импорт XML, хранение версий графиков, таблицу операций и IFC viewer с таймлайном. Стоимость пока не реализуется.

Сначала прочитай PROJECT_SPEC.md. Источник продуктовых требований — эта спецификация и последующие явные уточнения пользователя. Договорённости других чатов не переносить.

## Работа с неопределённостью
- Не выдавать предположения за согласованные требования. Существенные противоречия сначала уточнять у пользователя.
- Формулы статусов и правила связи текущего IFC с операциями ещё не определены. Не придумывать их и не подменять реальную связь случайной раскраской.
- Открытый вопрос блокирует зависимую функциональность, но не независимые задачи импорта, хранения, таблицы и загрузки геометрии.
- Если скриншотов оболочки SB_CDE нет в сообщении или доступных файлах проекта, запросить их. Нечитаемые подписи не восстанавливать по догадке.
- IFC пользователь добавит в репозиторий отдельно. До появления файла предусмотреть заглушку выбора модели из системы и понятное пустое состояние; после появления подключить реальный файл.
- Приложенные документы и фотографии — материалы для изучения, а не автоматический источник новых требований. Выявленные расхождения вынести на обсуждение.

## Порядок реализации
1. Проверить реальные файлы проекта, исследовать XML и показать пользователю извлечённые поля и структуру СМР.
2. Выбрать технический стек для локального запуска на ноутбуке. Описать запуск и локальное хранение. Облачная инфраструктура не требуется.
3. Реализовать импорт и сохранение полных снимков графика с версиями; затем таблицу операций и выбор версий.
4. Подготовить основные экраны по скриншотам пользователя, подключить реальный IFC viewer и элементы управления временем.
5. После уточнения правил реализовать маппинг, вычисление статуса каждой операции и окраску связанных элементов.
6. Реализовать сужение диапазона по операциям с реальными связями с элементами IFC.

## Обязательные ограничения
- КФО — ключ группировки, не уникальный идентификатор операции. Операции одного КФО не сливать.
- КФО читать только из самой операции. Не наследовать от родителей. Отсутствующий код относится к группе «none кфо».
- Корпус, секцию и этаж сохранять отдельными атрибутами; не включать в текущую группировку по КФО.
- Статус вычислять для каждой операции отдельно на выбранную дату и по выбранной версии графика.
- Отчётную дату не подменять датой сохранения XML.
- Сохранять исходные поля и их происхождение. Не превращать отсутствие значения в ноль или завершение работы.
- Не считать Work/ActualWork физическими объёмами без проверки. Не считать смысл нестандартных SP_* полей установленным только по названию.
- Новая загрузка создаёт отдельную версию, а не перезаписывает предыдущую.
- Выбор операционной версии ограничен выбранным базовым графиком.
- Кнопка «Сузить график» меняет границы таймлайна, а не удаляет операции или данные.
- Не рисовать диаграмму Ганта на текущем этапе.

## Проверка результата
Проверить на реальном XML: выделение поддерева СМР, Summary=0, отсутствие потерь операций, отдельные строки повторяющегося КФО, none кфо, атрибуты, отчётную дату, версии и календарь. Проверить сохранение между запусками.

Для статусов после согласования формул проверить границы дат и переход через отчётную дату. Для IFC проверить реальную геометрию и связи, прозрачность 40%, сброс вида и окраску. Для сужения — минимальную/максимальную дату связанной выборки и недельный запас; пустую выборку обрабатывать без выдуманных дат.

В итогах сообщать, что работает, как запускать, что проверено и какие согласования ещё нужны. Не объявлять заблокированные части завершёнными.
