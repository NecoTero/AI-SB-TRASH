# SB_CDE — локальный макет 4D/5D мониторинга

Дата фиксации требований: 19.10.2026.

## 1. Цель и границы
Создать с нуля макет инструмента мониторинга объекта: загрузить график, сохранить операции, связать их через сущность «Работы» с элементами IFC и показывать состояние строительства на выбранную дату.

Первая версия: реальный импорт XML, чтение всего раздела СМР, локальное хранение, версионность базовых и операционных графиков, таблица операций, IFC viewer одной модели и таймлайн. XLSX — будущий входной формат, сейчас импорт XLSX не нужен. Стоимость и финансовая аналитика пока не входят в реализацию. Сам график в виде диаграммы Ганта не рисуется.

## 2. Термины и сущности
| Сущность | Правило |
| --- | --- |
| Работы | Системная сущность/база данных для данных графиков и BIM; пользовательское представление импорта — таблица операций |
| Операция | Отдельная единица работ графика в разделе СМР; сохраняет свою строку, идентификаторы, сроки и объёмы |
| Группа КФО | Группировка операций только по коду КФО, без объединения их записей |
| Местоположение | Корпус, секция, этаж — отдельные настраиваемые идентификаторы детализации и связи с BIM |
| Версия графика | Отдельный снимок данных, создаваемый каждой загрузкой |
| Отчётная дата | Дата, разделяющая фактическую и плановую/прогнозную области выбранного графика |
| Связь с IFC | Связь операций через «Работы» с элементами модели; конкретные правила ещё согласуются |

IFC-элементы связываются с агрегированной сущностью «Работа», а не непосредственно с каждой операцией. В текущем макете отдельная связь элемента с операцией не создаётся. КФО всегда входит в идентификатор «Работы»; дополнительные системные идентификаторы пользователь выбирает при импорте, а выбранный состав действует для всех версий графика и может редактироваться на уровне «Работы».

Код КФО не уникален для операции. Даже операции одного КФО с одинаковым местоположением не сливаются автоматически. Статус относится к операции, а не к группе КФО.

## 3. Базовый и операционный графики
Базовый график — первоначальный договорной график и основа будущего анализа отклонений. Он может пересматриваться. Операционные графики направляются еженедельно без согласования: содержат факт в процентах и физических объёмах и уточнённый план.

Первая загрузка по умолчанию базовая; следующие по умолчанию операционные. Пользователь может изменить тип загружаемого графика. Каждый операционный график привязан к конкретному базовому. Оба типа имеют версионность.

В пользовательском интерфейсе версия обозначается смысловой меткой:
- `Базовый` — договорной снимок, к которому привязываются операционные загрузки;
- `Актуальный` — снимок с наиболее поздней отчётной датой, а при равной дате — импортированный позже;
- `Исторический` — любой более ранний операционный снимок.

Внутренние технические номера версий не показываются пользователю, остаются
неизменяемыми после записи и могут иметь пропуски после удаления. Если базовый
снимок одновременно является самым актуальным, интерфейс показывает
`Базовый · актуальный`.

В «Мониторинге» показывается только актуальная версия по отчётной дате; остальные версии видны в списке как недоступные с пояснением. Исторические версии пока можно выбирать в «Работах». Каждая загрузка создаёт новую версию. Переключение версии должно менять используемый снимок данных, а не смешивать операции разных снимков. Ручное изменение отчётной даты в «Работах» сохраняется в метаданных текущей версии после пятисекундной задержки и не создаёт новую версию.

Открытые детали: межверсионный ключ сопоставления операций; судьба отсутствующей в новом снимке операции для будущей аналитики; точная структура идентичности и редакций базового графика. До согласования не удалять исторические снимки и не утверждать стабильность UID/ID/WBS между файлами.

## 4. Импорт XML
### Область импорта
Считать всё поддерево СМР. Предварительно согласовано: в пользовательский перечень операций входят строки Summary=0, включая вехи. Родительские строки сохраняются для иерархии и извлечения местоположения, но отдельными операциями не отображаются. Это решение проверить с пользователем на результате импорта.

### Извлекаемые данные
- Все поля операций XML, включая вложенные и повторяющиеся структуры, без потери исходного представления.
- UID, ID, WBS и остальные идентификаторы, включая Spider_Code при наличии.
- Название, код и наименование КФО, сроки, плановые и фактические значения, проценты, объёмы и единицы измерения при наличии.
- Исходная иерархия и отдельные атрибуты корпуса, секции, этажа, извлекаемые из неё.
- Определения пользовательских полей: сохранять FieldID, имя/псевдоним и значение, а не привязываться только к номеру TextN.
- Рабочие календари, исключения и календарные ссылки операций.

КФО читается только из самой операции. Если его нет — операция попадает в «none кфо». Наследование КФО запрещено. КФО всегда участвует в идентичности работы; корпус, секция и этаж пользователь включает независимо при первой загрузке или позднее в настройках работ. Выбранный набор применяется ко всему модулю.

При извлечении местоположения сохранять исходный путь и источник значения. Правила распознавания названий и неоднозначных/составных этажей ещё уточняются. Не придумывать отсутствующее местоположение.

Результат для пользователя — плоская таблица операций со столбцами полей XML и группировкой по КФО. Конкретное отображение сложных/вложенных полей согласовать, сохранив доступ к исходным значениям.

В текущем макете действует жёсткий лимит 2 500 операций СМР в одном импорте. Если после чтения XML найдено больше операций, импорт не сохраняется, а пользователь получает сообщение с фактическим количеством и допустимым лимитом.

### Отчётная дата
Читать отчётную дату из XML. В приложенном образце есть Project/StatusDate. Если дата отсутствует — подставлять today; пользователь может редактировать её. Не использовать LastSaved как отчётную дату. Сохранять различие между исходной датой и пользовательским значением.

### Наблюдения по приложенному образцу
Источник: down_PL_CON_13.xml (локальная копия может иметь префикс 16-).
- Пространство имён: http://schemas.microsoft.com/project.
- В ветке «СМР» обнаружено 1 527 записей с Summary=0.
- У 1 243 из них непосредственно не заполнен «Код КФО»; наследование не применялось.
- Поле «Код КФО» определено через ExtendedAttributes, FieldID 188744009; Spider_Code — 188744016. Это наблюдения для данного файла, а не универсальные номера для всех экспортов.
- StatusDate: 2026-07-27T08:00:00; LastSaved: 2026-09-25T15:28:26.
- Есть SP_VolPlan и SP_VolFact. Их точное использование, единицы и соотношение с процентами проверить до расчётов.
- КФО 204.02.02.04 встречается у операций UID 1111, 1273, 1417 с разными сроками. Уникальность КФО не предполагается.

Не переносить эти контрольные количества на другие файлы. Смысл Start/Finish, вложенных Baseline и специальных полей сначала проверить; загруженный базовый график не отождествлять автоматически с вложенным XML Baseline.

## 5. Локальное хранение
Приложение запускается на ноутбуке пользователя. Данные хранятся локально. Технологию локального хранения выбирает агент; серверная/облачная база не требуется. Предусмотреть сохранение импортированных версий между запусками.

Хранить отдельные снимки, операции, исходную иерархию, календари, определения полей, отчётные даты, тип и связь графиков. Не перезаписывать предыдущие снимки новой загрузкой. Сохранение исходного XML как отдельного файла не согласовано; не путать этот вопрос с обязательным сохранением разобранных исходных полей.

## 6. IFC и статусы
Пользователь добавит IFC в репозиторий. Нужен реальный IFC viewer на основе одной модели и заглушка системного выбора модели. В текущем IFC кодов нет; правила его связывания описываются отдельно. В следующей модели ожидаются коды и атрибуты местоположения.

Статус рассчитывается для каждой операции на выбранную дату по выбранному графику. Связанные элементы окрашиваются соответственно. Формулы, приоритеты противоречивых фактических данных, преобразование процентов/объёмов в статус и разрешение нескольких операций у одного элемента пока открыты.

Предварительный набор статусов:
| Статус | Отображение |
| --- | --- |
| Выполнено | Зелёный |
| В работе | Зеленовато-синий, болотный оттенок; точный цвет уточняется |
| Не начато | Элементы скрыты |

Отсутствие согласованной формулы/связи не считать статусом «Не начато». Не красить элементы произвольно и не выдавать демонстрационные статусы за результат импорта.

## 7. Начальный вид и таймлайн
При первоначальном открытии или сбросе к начальному состоянию видна вся модель с прозрачностью 40% (непрозрачность 60%). При переходе к проигрыванию строительства общая модель скрывается; затем отображаются элементы операций в работе и выполненных операций в соответствующих цветах.

Таймлайн доступен для просмотра как базового, так и операционного графика. Нужны ручное перемещение и кнопка автопроигрывания. Переключаемый шаг: 1 рабочий день, 3 дня, 1 неделя; расчёт рабочих дней опирается на календарь XML. Как переводить недельный шаг в календарь и какой календарь брать при разных календарях операций — открытые детали, не подменять их пятидневкой.

Отчётная дата делит временную шкалу на факт и план/прогноз. Справа от неё просмотр продолжается по плановым срокам. Точные статусы по обе стороны определит позднее согласованная статусная модель. Само нахождение даты слева от отчётной даты не означает, что операция выполнена.

Не определены: начальная выбранная дата и полные границы шкалы; поведение точно на отчётной дате; скорость автопроигрывания; правила неполных дат.

## 8. Кнопка «Сузить график»
После маппинга «Работы» с операциями и элементами IFC возникает выборка операций, которые реально можно визуализировать. Нужна отдельная кнопка «Сузить график»: она меняет левую и правую границы таймлайна по минимальной и максимальной датам этой выборки с недельным запасом. Цель — рассматривать короткий визуализируемый участок без масштаба всего многолетнего графика.

Ограничение: наличие КФО само по себе не доказывает связь с IFC. Сужать по операциям с установленными связями, а не по всем операциям или всем операциям группы КФО. Сужение не меняет снимки, сроки и состав импортированных данных.

До реализации уточнить:
- какие поля дат участвуют в min/max: плановые, фактические или комбинация по статусной модели;
- недельный запас с каждой стороны и его календарная трактовка;
- учитывать ли текущие пользовательские фильтры/выделение;
- поведение при пустой выборке, пропущенных датах и выбранной дате вне новых границ;
- способ возврата к полному диапазону.

## 9. Основные экраны
Требуются следующие задачи интерфейса; способ размещения в экранах/панелях агент согласует по скриншотам:
1. Мониторинг: IFC viewer, начальный вид/сброс, легенда статусов, выбранная дата, отчётная дата, шкала, шаг, автопроигрывание, «Сузить график».
2. Импорт: выбор XML, тип графика (первая версия только базовая), привязка к базовому для операционного, автоматическое чтение отчётной даты с редактированием, выбор идентификаторов при первой загрузке, результат чтения и ошибки.
3. Работы: плоская таблица операций выбранного снимка, группировка по КФО и none кфо, поля XML и местоположение.
4. Выбор версий: базовая версия и относящиеся к ней операционные версии, отчётные даты и активный выбор.
5. Выбор модели из системы: пока заглушка; действующая модель берётся из репозитория после добавления пользователем.

Оболочка — по отдельно предоставленным скриншотам SB_CDE. Если агент не найдёт скриншотов, он должен запросить их. Проект уже задан контекстом модуля; новый выбор проекта не добавлять без запроса.

## 10. Приёмка и дальнейшие уточнения
Первый проверяемый результат: XML действительно прочитан, СМР выделен, операции сохранены без слияния, таблица отображает данные и КФО, версии выбираются в корректной связке, локальное хранение работает. IFC viewer открывает реальную модель после её предоставления.

Следующий результат после согласования правил: операция получает статус на выбранную дату, связанные элементы корректно отображаются, календарь управляет шагом, сужение использует связанную выборку.

Открытые бизнес-правила не заполнять предположениями. Обсуждать их тогда, когда требуется зависимая реализация; независимую работу продолжать.
