# Фильтрация работ по строительному этапу

## Назначение

Плашки «Все этапы», «Фундамент», `Shell&Core`, «Фасады», «Кровля» и `FitOut` фильтруют существующий реестр работ. Отдельная колонка этапа в таблицу не добавляется.

Единственный источник истины — производный признак `constructionStage` (`Строительный этап`) в каталоге признаков. Он сопоставляет распознанный Код КФО одному из пяти этапов. КФО без BIM и BIM-коды, находящиеся вне пяти этапов здания, мастер-значения этапа не получают.

## Правила

### Вкладка «График»

1. Для каждой операции берётся распознанный `kfo`.
2. По действующему признаку `constructionStage` вычисляется этап.
3. При выбранной плашке остаются только операции вычисленного этапа.
4. Сохранённый ранее текст `operation.stage` не используется для фильтра: это защищает экран от устаревшего значения в старой версии XLSX.

### Вкладка «Модели»

1. При обработке IFC для каждого элемента распознаётся КФО.
2. Из КФО вычисляется строительный этап.
3. Элементы группируются в работы по КФО + Корпус + Этаж; группа получает тот же производный этап.
4. Плашка фильтрует IFC-группы напрямую. Связанная операция графика для показа модели не требуется.

### «Все этапы»

Режим показывает весь реестр, включая КФО без этапа, строки без BIM, наружные сети, благоустройство, ПНР и «Без КФО». Выбор конкретного этапа такие строки исключает.

## Машиночитаемый контракт

```text
stageOfKfo(kfo, traits) -> stage | null
filterOperationsByStage(operations, "all", traits) -> all operations
filterOperationsByStage(operations, stage, traits) -> operations where stageOfKfo(operation.kfo) == stage
filterModelGroupsByStage(groups, "all") -> all groups
filterModelGroupsByStage(groups, stage) -> groups where group.stage == stage
```

Реализация находится в `dist/core.js`, применение на экране — в `dist/app.js`, справочник — в `dist/catalog-extension.js`. Контракт проверяется тестами `tests/core.test.cjs`.
