# Принятые основания макета

Рабочая редакция от 03.11.2026. Если экспорт БТ расходится с последующим прямым уточнением пользователя, в макете применено последнее уточнение. Это фиксация выбора для прототипа, а не правка исходных БТ.

| Область | Применённое решение |
| --- | --- |
| Версии XLSX | Успешный и частичный импорт создают v1, v2…; номера постоянны, архивирование их не освобождает. Восстановление доступно администратору проекта по уточнению в переписке. |
| Актуальная версия | Последняя загруженная неархивная. Восстановленная версия участвует в определении актуальной по исходному порядку загрузки. Текущий выбор просмотра при восстановлении сохраняется. Последнее — поведение прототипа для обсуждения. |
| Смена настроек | График хранит ранее распознанный состав; новые настройки применяются при новом импорте. Для IFC — уведомление и ручное обновление в настройках моделей. |
| Ошибки XLSX | Максимальная фактическая дата позже отчётной — ошибка всего импорта; конкретные фактические даты позже отчётной также фиксируются как ошибки операций. Пустое название операции — ошибка строки. Полностью пустая строка пропускается и не входит в счётчики по БТ 14.1 v27. |
| Отчётная дата | До импорта её можно задать вручную. Для сохранённой версии минимум равен самой поздней заполненной фактической дате её принятых операций. |
| Название работы | Код КФО и имеющиеся локализации через ` | `. В строке работы столбец названия операции/модели содержит прочерк. |
| IFC | Выбираются только обработанные системой версии. Пересчёт заменяет предыдущий результат. Поиск отдельно по всем трём признакам каждого элемента. Невалидные необязательные признаки отбрасываются. |
| Приоритет ключей IFC | По прямому уточнению пользователя от 03.11.2026 ключи признака проверяются сверху вниз, как описано в БТ 14.5. Первый ключ имеет наивысший приоритет. Это уточнение имеет приоритет над противоположной формулировкой БТ 14.2 v6. |
| Обновление каталога признаков | Сохранённый в браузере каталог больше не перекрывает расширенный встроенный перечень. При смене `TRAIT_CATALOG_REVISION` выполняется одноразовое объединение: сначала сохраняются пользовательские ключи, значения и варианты, затем добавляются отсутствующие позиции из актуального каталога. Обычные пользовательские правки после миграции не восстанавливаются самопроизвольно до следующей ревизии. |
| Черновые поля признака | Непустой последний атрибут в строке «Введите атрибут» фиксируется автоматически при переходе к настройке значений для КФО, Корпуса и Этажа. Пустое поле не создаёт запись. Кнопка `+` и Enter остаются быстрыми способами добавить ещё одну строку, но не обязательны для сохранения последней. |
| Варианты КСП от 27.09.2026 | Точные строки корпусов («Корпус А оси А2-М / 1-9», Б и В) и этажей с отметками из обновлённого файла факта добавлены как допустимые варианты существующих мастер-значений. В реестре и кодах работ сохраняются единые системные значения «Корпус А/Б/В», «Этаж N». |
| Этап операции | Значение импортного XLSX хранится в `AK` (`Constraction Stages`) и сохраняется в снимке операции для трассировки импорта. Если ячейка пуста, при импорте может быть записан этап из КФО. Экранный фильтр не доверяет этому сохранённому тексту и всегда использует актуальный производный справочник. |
| Этап как признак | Строительный этап реализован как производный классификационный признак от уже распознанного КФО, а не как четвёртая часть идентичности работы. Это сохраняет сопоставление графика и IFC по КФО + Корпус + Этаж и позволяет использовать один актуальный маппинг для обеих вкладок. Коды вне пятиэтапного справочника остаются без этапа (`-`). |
| BIM как граница маппинга этапов | Источник признака — колонка `BIM` листа `DATA`: `✅` трактуется как `BIM`, `❌` и `•` — как `без BIM`. Строительный этап назначается только BIM-кодам. Для строк без BIM мастер-значение этапа не создаётся; в контрольной Excel-таблице показывается технический `-`, а уверенность и основание остаются пустыми. Земляные работы также исключены. BIM-коды наружных сетей, благоустройства, спортивных покрытий и ПНР остаются с `-`, поскольку не входят в пять этапов здания. |
| Плашки этапов в реестре | Фильтр не использует сохранённый `operation.stage`. На вкладке «График» этап заново определяется по КФО операции и текущему признаку `constructionStage`; на вкладке «Модели» используется этап IFC-группы, вычисленный при маппинге элементов. Поэтому модель показывается в своём этапе и без связанной операции графика. «Все этапы» не исключает строки без этапа. Колонка этапа в реестр по прямому решению пользователя не добавляется. |
| Кеш IFC | Содержимое файла идентифицируется SHA-256. Кеш свойств и бинарной геометрии переиспользуется после переименования, переноса или изменения даты файла, если его байты не изменились. Системное время файла не является идентификатором кеша. URL геометрии получает SHA-256, а ETag позволяет браузеру переиспользовать неизменившийся бинарник; обязательная ревалидация сохраняет работоспособность прототипной очистки кеша. |
| Производительность маппинга | Нормализованные ключи признаков и допустимые варианты мастер-значений компилируются в словари и переиспользуются. Параметры элемента подготавливаются одним проходом; семантика приоритета и первого допустимого значения сохраняется. |
| 3D: видимость и статусы | Верхний счётчик моделей убран. Слева показано дерево загруженных IFC с глазом для каждой модели; всё дерево сворачивается в узкую боковую кнопку-шторку без изменения видимости моделей. Скрытая модель исключается из отрисовки, счётчиков статусов и фокуса BIM. Каждая группа легенды, включая «Без КФО или связи», независимо скрывается и показывается; несвязанные элементы по умолчанию скрыты. |
| 3D: время | Статусы не сохраняются заранее для каждой даты. При изменении даты `aggregateStatusAt` вычисляется заново для связанных операций каждого элемента. Воспроизведение поддерживает 1/3/7 дней и календарный месяц; шкала показывает реальные начала месяцев. |
| 3D: цвета таймлайна | Цвета зелёный/синий/серый зарезервированы за статусами и окраской IFC-элементов. Зоны относительно отчётной даты не используют статусные цвета: факт показан сплошным нейтральным серым, план — светлой штриховкой, граница отчётной даты — оранжевой линией. |
| Презентация процесса | В «Сценариях макета» добавлена локальная HTML-презентация из пяти экранов. Главный акцент — текущая подготовка ИД: отдельные ветви IFC и графика, очистка КФО/корпуса/этажа, независимое формирование работ системой, их сопоставление и просмотр статусов во viewer. Скрипт разворачивания иерархического графика явно отмечен как дорабатываемый. Основание — прямое описание пользователя и материалы `BIM_user_journey_final.pptx`, `Grafik_rebuilt_final.pptx`, `Monitoring_functions_final.pptx`; открытые будущие функции из материалов не выдаются за текущую реализацию. |
| Презентация: иллюстрации | Каждый этап текущего процесса сопровождается экранной миниатюрой в визуальном языке прототипа: настройки признаков IFC, плоская таблица графика, независимая обработка источников и статусный 3D-viewer. Иллюстрации собраны в HTML/CSS, поэтому масштабируются вместе с презентацией и не зависят от устаревающих скриншотов. |
| 3D: текущие работы | Под легендой статусов расположена отдельная сворачиваемая шторка. В ней показываются только связанные с видимыми моделями работы в статусах «В работе» и «Завершено» на выбранную дату. Активные работы идут первыми, более поздно начавшиеся — выше; завершённые переходят вниз и сортируются от недавно завершённых к более ранним. Работа раскрывается до операций с индивидуальным статусом и диапазоном дат. Список учитывает скрытие моделей и групп статусов и пересчитывается при перемещении по таймлайну. Для переключателя используется единая SVG-стрелка с округлённым штрихом. Панель явно сбрасывает общий `aside`-отступ, поэтому переключатель остаётся по центру и в раскрытом, и в свёрнутом состоянии. |
| Сценарии макета | Пока оставлен только текущий бизнес-процесс: кнопка «Сценарии макета» открывает презентацию напрямую, без промежуточной сетки демонстрационных сценариев. Схематичное изображение статусной модели заменено снимком реального локального 3D-viewer с IFC `1816_PSK_RD_KR_M3_R24.ifc`; воспроизводимый снимок хранится в `dist/assets/status-viewer.png`, служебный сценарий — в `scripts/capture-viewer.mjs`. |
| Чтение наборов свойств IFC | Экземплярные и типовые наборы читаются раздельно. Пустой `HasPropertySets` у типа считается отсутствием типовых наборов, а не ошибкой всей модели; повторяющиеся типы кешируются в рамках одного разбора. Неудача конкретного задания не переводит доступную версию IFC в состояние «Обработка». |
| Прототипные действия | «Обновить BIM» обходит серверную memo-копию, принудительно вычисляет SHA-256 всех выбранных IFC и заново формирует группы работ. При совпадении SHA переиспользуются свойства, при отличии IFC разбирается заново. Результат подтверждается отдельным окном со счётчиками. «Очистить хэш» удаляет кеш свойств и геометрии и заставляет модели пересобраться при следующем использовании. Архивирование и восстановление версий графика также оставлены только для демонстрации прототипа. Все действия помечены тултипами и не входят в MVP. |
| «Без КФО» | Строка работы, раскрываемая до исходных моделей. Статус строки и моделей — «Нет данных». |
| Результат IFC | Зелёное окно: по каждой модели всего элементов, с распознанным КФО, без распознанного КФО. |
| Уведомления | Причины «изменились признаки» и «новая версия модели» отражаются в тултипе индикатора. Для модели показаны выбранная версия и плашка «Неактуально». |
| Отменённое напоминание | Требование вести технические даты изменения справочника и напоминание дописать это в 14.5 отменены пользователем. |

## Расхождения исходных материалов

1. В 14.5 v19 приоритет ключей описан сверху вниз, а в 14.2 v6 поиск для IFC задан **снизу вверх**. По прямому уточнению пользователя от 03.11.2026 в макете применяется правило 14.5 — сверху вниз. Текст 14.2 перед передачей в разработку нужно привести к этому решению.
2. В 14.1 v27 ПР-38 запрещает повторный маппинг ранее загруженной версии, но UC-04 всё ещё говорит о пересчёте по действующим настройкам. В макете применяется ПР-38 как подробное бизнес-правило: смена версии не запускает повторный маппинг.
3. Название работы в примере 14.1 с дефисами заменено в макете согласованным разделителем ` | `.
4. В 14.1 есть пример первой строки 8, хотя шаблон задаёт первую операцию в строке 4. Номер в отчёте макета — исходная строка листа, начиная с 4.
5. Начальные таблицы 14.5 содержат ключи, помеченные в самом документе как «В ПРОЦЕССЕ». Их содержимое использовано как демонстрационное начальное наполнение; исключён повтор «SB_Корпус» после нормализации.

## Что здесь демонстрационное

Названия проекта, файлы моделей, авторы, количество элементов и строки операций созданы для макета. Данные конкретной версии IFC демонстрируются одним подготовленным набором параметров на модель; разные геометрические слепки версий не моделируются. Вкладка IFC не получает графиковые сроки и операции до реализации 14.3.
