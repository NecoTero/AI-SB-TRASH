# Принятые основания макета

Рабочая редакция от 02.11.2026. Если экспорт БТ расходится с последующим прямым уточнением пользователя, в макете применено последнее уточнение. Это фиксация выбора для прототипа, а не правка исходных БТ.

| Область | Применённое решение |
| --- | --- |
| Версии XLSX | Успешный и частичный импорт создают v1, v2…; номера постоянны, архивирование их не освобождает. Восстановление доступно администратору проекта по уточнению в переписке. |
| Актуальная версия | Последняя загруженная неархивная. Восстановленная версия участвует в определении актуальной по исходному порядку загрузки. Текущий выбор просмотра при восстановлении сохраняется. Последнее — поведение прототипа для обсуждения. |
| Смена настроек | График хранит ранее распознанный состав; новые настройки применяются при новом импорте. Для IFC — уведомление и ручное обновление в настройках моделей. |
| Ошибки XLSX | Максимальная фактическая дата позже отчётной — ошибка всего импорта; конкретные фактические даты позже отчётной также фиксируются как ошибки операций. Пустое название операции — ошибка строки. Полностью пустая строка пропускается и не входит в счётчики по БТ 14.1 v27. |
| Отчётная дата | До импорта её можно задать вручную. Для сохранённой версии минимум равен самой поздней заполненной фактической дате её принятых операций. |
| Название работы | Код КФО и имеющиеся локализации через ` | `. В строке работы столбец названия операции/модели содержит прочерк. |
| IFC | Выбираются только обработанные системой версии. Пересчёт заменяет предыдущий результат. Поиск отдельно по всем трём признакам каждого элемента. Невалидные необязательные признаки отбрасываются. |
| «Без КФО» | Строка работы, раскрываемая до исходных моделей. Статус строки и моделей — «Нет данных». |
| Результат IFC | Зелёное окно: по каждой модели всего элементов, с распознанным КФО, без распознанного КФО. |
| Уведомления | Причины «изменились признаки» и «новая версия модели» отражаются в тултипе индикатора. Для модели показаны выбранная версия и плашка «Неактуально». |
| Отменённое напоминание | Требование вести технические даты изменения справочника и напоминание дописать это в 14.5 отменены пользователем. |

## Расхождения исходных материалов

1. В 14.5 v19 приоритет ключей описан сверху вниз, а в 14.2 v6 поиск для IFC задан **снизу вверх**. В макете IFC применяется прямое правило 14.2 — снизу вверх. Перед передачей требований в разработку направление нужно согласовать между документами.
2. В 14.1 v27 ПР-38 запрещает повторный маппинг ранее загруженной версии, но UC-04 всё ещё говорит о пересчёте по действующим настройкам. В макете применяется ПР-38 как подробное бизнес-правило: смена версии не запускает повторный маппинг.
3. Название работы в примере 14.1 с дефисами заменено в макете согласованным разделителем ` | `.
4. В 14.1 есть пример первой строки 8, хотя шаблон задаёт первую операцию в строке 4. Номер в отчёте макета — исходная строка листа, начиная с 4.
5. Начальные таблицы 14.5 содержат ключи, помеченные в самом документе как «В ПРОЦЕССЕ». Их содержимое использовано как демонстрационное начальное наполнение; исключён повтор «SB_Корпус» после нормализации.

## Что здесь демонстрационное

Названия проекта, файлы моделей, авторы, количество элементов и строки операций созданы для макета. Данные конкретной версии IFC демонстрируются одним подготовленным набором параметров на модель; разные геометрические слепки версий не моделируются. Вкладка IFC не получает графиковые сроки и операции до реализации 14.3.
