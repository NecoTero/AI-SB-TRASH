# КСУП BIM · интерактивный макет

Локальный макет экранов 14.1, 14.2 и 14.5. Основа: БТ 14.1 v27, БТ 14.2 v6, БТ 14.5 v19 и ФТ 14.5 v23 из папки `Бизнес и системные требования`. Компоновка пересобрана по экранам `Дизайн/Макет.docx`: общая панель управления в окне «Работы», выпадающие версии графика, календарь под полем даты, компактный импорт, настройка моделей и системный экран с двухшаговым редактором признаков. Соответствия экранов перечислены в `docs/design.md`.

## Как запустить завтра

Запускайте прототип через `npm run dev`: локальный сервер нужен для автоматического чтения папки с IFC-моделями.

**В VS Code через Live Server:**

1. Распакуйте весь архив.
2. В VS Code выберите **File → Open Folder** и откройте папку `sb-cde-prototype`.
3. Установите расширение **Live Server**, если его ещё нет.
4. Нажмите правой кнопкой на `dist/index.html` → **Open with Live Server**.

**Через Node.js, без зависимостей:** если Node.js уже установлен, откройте терминал VS Code в корне проекта:

```sh
npm run dev
```

Откройте `http://localhost:5173`. Команда `npm install` не нужна. Для автоматических проверок ядра нужна Node.js 18+; выполните `npm test`.

## Что проверить

1. На вкладках «График» и «Модели» проверить плашки этапов. График фильтруется по актуальному маппингу КФО операций, модели — по производному этапу IFC-групп; отдельная колонка этапа в реестр не добавляется.
2. «График СМР v3»: выбрать старую версию, архивировать и восстановить версию. Номера сохраняются. Актуальная определяется порядком загрузки среди неархивных. Архивирование и восстановление — сценарии прототипа, не входящие в MVP; это отмечено в тултипах действий.
3. Отчётная дата: попытаться выбрать дату раньше максимального факта — сохранение блокируется.
4. «+ График»: загрузить свой XLSX либо использовать демонстрационный. Демонстрационный файл содержит одну операцию без названия — получится частичный импорт. В «Сценариях макета» есть вариант ошибки всего графика.
5. Положить `.ifc` в `Исходные данные/IFC модели` и открыть «+ Модель»: файлы появятся в окне вместе с размером и датой. Версии задаются суффиксами `v1`, `v2` и т. д. (`Model A v1.ifc`, `Model A v2.ifc`). Файл без суффикса считается v1. «Обновить BIM» принудительно заново вычисляет SHA-256 выбранных версий и всегда повторяет маппинг работ; неизменённый файл берётся из кеша свойств, изменённый — разбирается заново. После операции показываются число проверенных и изменённых моделей и итоговая таблица. Кеш свойств и геометрии определяется SHA-256 содержимого, поэтому переименование или изменение даты файла не запускает повторный разбор. Служебная кнопка «Очистить хэш» удаляет кеш и существует только в прототипе.
6. Вкладка «Модели»: раскрыть работу до моделей; «Без КФО» отображается как строка работы со статусом «Нет данных».
7. По умолчанию выбрана роль «Администратор». Открыть «Системные настройки» через значок настроек или меню аватара. Наименование признака заблокировано; можно редактировать ключи, МЗ и допустимые варианты. «Строительный этап» показан отдельной карточкой как производный признак: его источник — распознанный Код КФО, поэтому этап не входит в код работы. Последний введённый ключ автоматически добавляется при переходе к настройке значений — отдельное нажатие `+` не требуется; пустая строка игнорируется.
8. Роль «Пользователь» предназначена только для просмотра. Вернуть роль «Администратор», чтобы выполнять импорт и менять настройки.
9. «Сценарии макета» позволяют открыть HTML-презентацию текущего бизнес-процесса, показать пустое состояние, изменения признаков, новую версию IFC и вернуть исходные демоданные. Презентация состоит из пяти экранов: общая цепочка, подготовка IFC, подготовка графика, обработка системой и просмотр результата.

Изменения сохраняются в `localStorage` этого браузера. При обновлении встроенного каталога прототип один раз дополняет старую локальную копию новыми ключами, мастер-значениями и допустимыми вариантами, сохраняя всё добавленное пользователем. Номер каталога задаётся константой `TRAIT_CATALOG_REVISION`; при следующем обновлении исходного перечня её нужно изменить. Для чистого старта используйте «Сценарии макета → Сбросить демоданные». Разные адреса (`file://`, Live Server и localhost) имеют отдельные локальные данные.

## Проверка этой сборки

Пройдены 34 автоматические проверки распознавания, группировки и валидации, включая фильтрацию графика и IFC-моделей по этапам, сквозное чтение реальных заполненных XLSX и копии справочника КФО с этапами. Базовый план успешно принимает 885 операций, обновлённый файл факта — 841 операцию. Для справочника отдельно проверяются 193 строки, 192 уникальных кода, отметки BIM/без BIM, распределение по этапам и сохранение исходного дубля кода.

Дополнительно проверена загрузка настоящего XLSX через файловый диалог: выбран лист «График», считана отчётная дата 27.10.2026, импортированы обе операции и сформирована одна работа. Тестовый файл доступен в `examples/qa_import_fixture.xlsx`. Запуск двойным щелчком и мобильная компоновка в этой сборке отдельно не проверялись.

## Реализованное поведение и границы

| Часть | Поведение макета |
| --- | --- |
| XLSX | Реальный выбор файла и листа. Отчётная дата B1; заголовки в строке 3; операции со строки 4; B/K/R/S/T/U/AI/AJ/AK. Колонка AK содержит этап операции. Полностью пустые строки пропускаются и не входят в счётчики. Даты читаются как даты Excel, включая локализованный формат ДД.ММ.ГГГГ. |
| Проверка графика | КФО обязателен; непустые неизвестные КФО/Корпус/Этаж отклоняют график. Максимальный факт позже отчётной даты отклоняет график; соответствующие строки также попадают в отчёт как ошибки операций. Ошибки названия операции и остальных правил дат исключают строку. Без допустимых операций версия не создаётся. |
| Отчёт импорта | Скачивается CSV с разделителем `;` и UTF-8 BOM. Это упрощение формата отчёта для макета. |
| Версии графика | Сохранённые операции и распознанные значения — отдельный снимок. Изменение признаков и выбор старой версии не запускают повторный маппинг графика. |
| IFC | Сервер читает выбранные версии `.ifc` из `Исходные данные/IFC модели` через `web-ifc`, извлекает элементы, экземплярные и типовые наборы свойств. Пустые типовые наборы допустимы, а повторяющиеся типы кешируются в рамках разбора. Свойства и геометрия кешируются по SHA-256 содержимого: файл повторно разбирается только при изменении байтов либо после явной прототипной очистки кеша. |
| Поиск признаков IFC | Для каждого элемента отдельно ищутся Код КФО, Корпус и Этаж. Строительный этап затем вычисляется из распознанного КФО как производный признак. Ключи проверяются сверху вниз по приоритету 14.5 до первого допустимого значения; в повторяющихся параметрах — первое допустимое. Нормализованные ключи и допустимые варианты компилируются в словари и переиспользуются, чтобы не выполнять вложенный поиск по всему справочнику для каждого параметра. |
| Нормализация | Полная строка; игнорируются регистр и крайние пробелы; визуально равнозначные латинские/кириллические буквы приводятся. Внутренние пробелы, подчёркивания, ведущие нули и минус сохраняются. |
| Сопоставление | Операции графика и IFC-группы сопоставляются по полному коду работы: КФО + Корпус + Этаж. Во вкладке моделей отображаются сроки, статус и число операций; во вкладке графика — число IFC-элементов. «Только с BIM» оставляет совпавшие работы. |
| Этапы работ | На экране «Работы» доступны «Фундамент», `Shell&Core`, «Фасады», «Кровля» и `FitOut`. Производный справочник содержит только КФО, помеченные `BIM` на листе `DATA`: земляные работы и пять кабельных КФО с отметкой `без BIM` исключены. На вкладке «График» этап вычисляется из КФО операции по актуальному справочнику, поэтому устаревший текст этапа из XLSX не влияет на фильтр. На вкладке «Модели» фильтруются IFC-группы по их производному этапу, даже если связанной операции графика нет. «Все этапы» показывает также строки без этапа и «Без КФО». Подробный контракт: `docs/stage-filtering.md`. |
| 3D и таймлайн | Реализован локальный просмотр геометрии выбранных IFC, статусная раскраска, календарь и таймлайн. Слева находится сворачиваемая шторка дерева моделей с индивидуальной видимостью; легенда и статистика учитывают только показанные модели. Группы статусов переключаются кликом. Под легендой находится сворачиваемый список текущих работ: активные работы идут сверху, завершённые переходят вниз, а каждая работа раскрывается до операций. Список синхронизирован с датой, видимостью моделей и статусными фильтрами. Доступны шаги 1/3/7 дней и 1 календарный месяц; на шкале нанесены границы месяцев. Статус вычисляется на лету для выбранной даты, заранее календарь статусов не материализуется. Геометрия подготавливается сервером и сохраняется в бинарном кеше по SHA-256 исходного IFC; браузер хранит бинарник в отдельной записи для каждого хеша и при повторном открытии проверяет его по ETag без повторной передачи неизменившихся данных. Формальное БТ 14.4 ещё не сформировано, поэтому поведение считается прототипным. |
| Роли | Две роли: администратор выполняет все действия, пользователь работает в режиме просмотра. По умолчанию выбрана роль администратора. Это интерфейсная модель прав, без авторизации и серверной защиты. |
| Настройки | Полные начальные ключи и варианты взяты из таблиц 14.5 и дополнены фактическими вариантами Корпусов А/Б/В и этажей из обновлённого файла факта от 27.09.2026. Повтор «SB_Корпус» после нормализации объединён в один ключ. Карточка «Строительный этап» помечена как производная от КФО; её варианты содержат 89 BIM-кодов, сопоставленных пяти этапам. При обновлении системного справочника устаревшие КФО этапов удаляются из локальной копии. В карточках и редакторе показывается фактическое количество ключей и значений. Добавленные в прототипе ключи, значения и варианты сохраняются и сразу участвуют в отображении и последующем маппинге. Системное сохранение в макете формирует уведомление о признаках. |

## Где что менять

```text
dist/index.html    — точка входа
dist/styles.css    — базовые стили
dist/reference.css — компоновка и оформление по Дизайн/Макет.docx
dist/app.js        — экраны, формы и действия
dist/core.js       — распознавание, группировка и валидация
dist/data.js       — начальные справочники и демомодели
dist/xlsx.js       — чтение XLSX по шаблону
dist/vendor/       — JSZip и лицензия
server.mjs        — локальный сервер и каталог IFC
file-content-hash.mjs — SHA-256 исходных IFC и память вычисленных хешей
ifc-reader.mjs    — чтение элементов и свойств IFC через web-ifc
viewer-geometry.mjs — подготовка и кеш бинарной 3D-геометрии
tests/            — автоматические проверки ядра
tools/build_import_templates.ps1    — сборка двух импортных XLSX из исходников
tools/validate_import_templates.ps1 — полная сверка созданных XLSX
docs/decisions.md — применённые решения и расхождения источников
docs/design.md    — соответствие экранов документу с дизайном
```

Шрифты системные, иконки встроены в код, внешних CDN нет. Прототип не отправляет загруженные данные на сервер.
