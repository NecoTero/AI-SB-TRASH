# Постоянная инструкция для чтения XML-графиков работ (Microsoft Project)

Используй это правило **каждый раз**, когда пользователь предоставляет XML-график задач Microsoft Project и просит извлечь работы, коды, даты или объёмы.

## Обязательный алгоритм

1. Обрабатывать XML **программно**, а не вручную по частям текста. Основной скрипт в этом комплекте: `parse_msproject_xml.py`. Команда: `python parse_msproject_xml.py <путь_к_XML> --out <каталог_результатов>`.
2. Учитывать XML namespace проекта. Читать задачи **только** из `Project/Tasks/Task` в исходной последовательности. Не смешивать их с `Resources`, `Assignments` и другими узлами.
3. Считать **каждый Task**, включая корневой Task, суммарные задачи (`Summary=1`), обычные задачи и вехи. Ничего не удалять и не объединять по имени.
4. Получать `UID`, `ID`, `Name`, `WBS`, `OutlineNumber`, `OutlineLevel`, `Summary`, `Milestone` как отдельные поля.
5. Пользовательские реквизиты (`Код проекта`, `Код CBS`, `CBS`, `Код КФО`, `КФО`, `Spider_Code`, `Код работ из раздела ПИР`) извлекать через сопоставление `Project/ExtendedAttributes/{FieldID, Alias}` и `Task/ExtendedAttribute/{FieldID,Value}`. Не зашивать произвольные FieldID в общие правила.
6. Сохранять разные идентификаторы раздельно: `UID` — идентификатор задачи XML, `ID` — исходный номер, `WBS` — код структуры, `Spider_Code` — пользовательский код (`task_code` экспорта), `Код работ из раздела ПИР` — ещё один отдельный код. Не считать `Spider_Code` уникальным, пока не проведена проверка.
7. Строить дерево **по порядку задач и OutlineLevel**. `parent_uid` — предыдущий открытый узел уровня на единицу меньше. Проверять `WBS` и `OutlineNumber`, но не подменять ими исходную вложенность. Ничего не сортировать по имени.
8. Одновременно формировать два представления **одного набора**: плоскую таблицу со всеми атрибутами каждой задачи и дерево с точно теми же узлами и атрибутами. Обязательно формировать CSV + SQLite для таблицы и JSON + TXT для дерева; Excel — если есть поддержка.
9. Из каждой работы извлекать даты `Start`, `Finish`, `ActualStart`, `ActualFinish`, `EarlyStart`, `EarlyFinish`, `LateStart`, `LateFinish`, `ConstraintDate`, `Deadline`, `Stop`, `Resume`, если они есть. `Project/StatusDate` — поле **проекта**, не фактическая дата работ. Не переименовывать `Start/Finish` в утверждённый базовый план без источника.
10. Из каждой работы извлекать плановый объём `SP_VolPlan`, фактический объём `SP_VolFact`, стоимостной показатель `SP_VolCost` и процент `PercentComplete` отдельно. Не высчитывать объёмы или факт из процента, не угадывать единицы измерения.
11. **Любое отсутствие поля сохранять как NULL**, а не `0`, дату проекта или значение родителя. `0` в XML считать реальным значением. Не заполнять коды CBS/КФО от родителя, если нет прямого пользовательского требования.
12. Сохранять все дополнительные скалярные значения XML в колонках `xml__...`, все пользовательские поля — в `ext__<FieldID>`, нестандартные вложенные структуры — в `nested_xml_json`. Так не терять неожиданно новые поля экспорта. Если бизнесу нужно нормализовать вложенный Baseline/TimephasedData, сообщить, что это отдельный шаг, а не выдавать вложенный JSON за обычные столбцы.
13. После обработки сверять число исходных `<Task>` с числом строк CSV/SQLite и количеством узлов JSON; проверять уникальность UID, родительские связи, порядок и глубину WBS. Ошибки и предупреждения выдавать отдельным отчётом `validation_report.json`.
14. Каждый импорт сопровождать метаданными проекта (`Name`, `Revision`, `StatusDate`, `LastSaved`) и контрольной суммой `SHA-256` исходного XML. Не объявлять идентификаторы задач неизменными между версиями без процедуры сопоставления.
15. При описании результатов отличать фактические поля XML от выбранных правил экспорта. Если поле или его смысл не подтверждены XML, сообщить об этом прямо.

## Контрольный образец

Для файла `down_PL_CON_13.xml` ожидается **3134** Task, из них **744** суммарных и **2390** несуммарных, уровни `OutlineLevel=0…8`.

**Важно:** данная инструкция не запускает скрипт автоматически сама по себе. Чтобы использовать её в другом чате или проекте, нужно также предоставить скрипт и XML-файл, либо разместить скрипт в доступном рабочем окружении.
